# AI 履歷工坊

把你的工作紀錄丟進一個資料夾，對 Claude Code 說一句「幫我做履歷」。它會讀完資料、寫初稿，再用 HR、面試官、你自己三種視角加事實查核反覆審閱，最後給你 Word 和 PDF。履歷上每個數字都對得回你的檔案，別人做的事不會被寫成你做的。

## 三步開始

1. **放資料**：把舊履歷、月報週報、簡報、專案清單、績效評語，通通丟進 `input/`。不用分類，pptx、docx、pdf、html、md、txt 都可以。有 DRM 的 PDF 讀不到，請放原始檔。
2. **打開 Claude Code**，在這個資料夾輸入：
   ```
   /resume
   ```
3. **回答問題**。它只會問你三次：一開始問你想投什麼、最想被看到什麼；中間問一次來源裡看不出來的事（例如某件事是你做的還是團隊做的）；最後問要不要再修。

十到二十分鐘後，`output/` 裡會有：

| 檔案 | 用途 |
|---|---|
| `<姓名>_履歷.pdf` | 直接投遞 |
| `<姓名>_履歷.docx` | 自己微調 |
| `<姓名>_履歷.md` | 原稿 |
| `投遞前確認.md` | 哪幾句只有你能拍板、面試會被問什麼、每個數字的出處 |

## 之後想改

直接用一句話說：

- 「不夠好，再修一版」
- 「我要改投 AI 產品經理」
- 「太長了，壓到一頁」
- 「給我英文版」
- 「只要重新輸出 Word」

不用重跑全部。

## 它怎麼審

每一輪有四個角色同時看稿：

- **HR**：7 秒內能不能抓到你是誰、關鍵字有沒有對到職缺、格式能不能過 ATS。
- **面試官**：逐句戳，列出面試會追問的問題；寫得撐不住的句子會被標出來。
- **你自己**：檢查有沒有被寫得太保守、像不像你講話、替你準備每個數字的說法。
- **事實查核**：每個數字、日期、「主導」「開發」對回原始檔案。

意見合成一張計分卡，寫手修出下一版。分數收斂就停，通常兩輪。每輪的審閱和分數都留在 `work/reviews/`，你可以回頭看它為什麼改、為什麼不改。

定稿前還有一個**編輯**角色專門去 AI 味：刪空話、換台灣用語、修節奏和標點，數字一個都不動。有裝 `humanizer-zh-tw` 外掛會直接用，沒裝也有內建的檢查表，效果接近。

## 它不做的事

- 不編數字。沒有數字就用規模撐，並提醒你去量。
- 不替你決定要不要寫「主導」。來源有依據就寫，沒有就問你。
- 不保證面試。它保證的是履歷上每一句你都講得清楚。

## 需要什麼

- Claude Code
- Python 3.10 以上（`/resume` 會自己裝 `python-docx`、`pymupdf`）
- PDF 輸出用 Windows 的 Microsoft Word；沒有的話會給你 Word 檔，自己另存 PDF

## 給想改流程的人

- `profile.md`：你的側寫，`/resume` 第一次會自動建立，之後可以手改。
- `references/`：寫作原則、風格規則、角色歸屬規則。改這裡等於改所有代理的標準。
- `.claude/agents/`：六個角色的提示詞（寫手、HR、面試官、求職者、事實查核、編輯）。
- `references/humanizer_checklist.md`：去 AI 味檢查表，編輯角色沒有外掛時照這份改。
- `.claude/skills/`：`/resume` 之外還有分段指令 `/resume-extract`、`/resume-facts`、`/resume-draft`、`/resume-review-loop`、`/resume-export`，想只跑某一段時用。
- `prompts/`：子代理用的提示詞範本與 Workflow 版迴圈腳本。

`input/`、`work/`、`output/`、`profile.md` 都在 `.gitignore`，分享專案時不會帶出個人資料。
