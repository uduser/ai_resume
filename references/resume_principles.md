# 優秀履歷撰寫原則（網路研究摘要，2026-09-11）

本檔是 review loop 的評分依據。來源 24 個，列在文末。原則會過時，若距今超過一年請重新跑 `prompts/00_research_principles.md`。


## 頂層原則

1. 招募者初篩平均 7.4 秒，先看現職職稱、公司、日期。（Ladders 眼動研究、HR Dive）
2. 每條 bullet 用 XYZ：完成 X，以 Y 衡量，透過 Z。（Google 前人資長 Laszlo Bock；Teal、Resume.io）
3. 動詞開頭、量化結果、不用被動語態。（Harvard Mignone Center）
4. 每段經歷交代 What／How／Impact，並寫團隊規模與跨部門對象；技術寫在該段經歷內，不要全塞技能區。（Y Combinator）
5. 寫戰果不寫職責；若一條 bullet 放在中階工程師履歷也成立，就還不夠資深。（SignalRoster、104 職場力）
6. 關鍵字對齊 JD，在職稱、經歷、技能三處出現。（LinkedIn）
7. Greenhouse 類 ATS 不做關鍵字淘汰，是人工按評分卡打分；履歷要讓招募者能直接把成果抄進評分卡。（Jobscan）
8. 單欄、標準標題、無表格圖示、Word 匯出 PDF。（Cake）
9. 資深者最多兩頁，每段 2～4 條。（Y Combinator、Cake）
10. ML／AI 職缺寫成效不寫工具清單：準確率、延遲、成本、上線規模的前後對比。（IGotAnOffer、Resume Worded）

## 主管兼工程師

- Player-coach 把 Technical Contribution 與 Leadership 拆兩組 bullet；Summary 第一句就宣告雙身分。（Teal、CareerBldr）
- 帶人數寫「人數＋組成＋結果」；預算寫「金額＋節省或如期比例」；跨部門寫「對象＋共同產出」。（Resume Worded、Y Combinator）
- 主管職常見錯誤：技術細節太多、管理成果無數字、沒把 AI 專案連到 ROI。（Teal Director of AI）

## 生成式 AI 導入，hiring manager 想看的證據

| 面向 | 指標 |
|---|---|
| 規模 | 帳號數、部門數、廠區數、工具與版本 |
| 採用率 | Active users %、WAU／MAU、seat 使用率；基準 6～12 個月 50～70%（MetricHQ） |
| 開發者生產力 | Copilot／Codex／Claude Code 的 DAU、接受率、PR 合併時間（GitHub Docs 提醒是方向性關聯，非因果） |
| 治理 | 使用規範、PII 規則、SSO 帳號管理、Shadow AI 下降（Liminal；Knostic：75% 企業有政策、僅 36% 有正式框架） |
| 訓練與變革 | 場次、人數、完訓率、種子人數（Worklytics） |
| 內部案例 | 案例數與前後對比、被複製到其他部門的數量 |
| 成本 | 授權費、每活躍使用者成本、回收 seat |
| 高層 | 簡報層級、取得預算 |

## 台灣 HR 格式偏好

- 十年以上兩頁；每段 2～4 條。（Wordvice、Cake）
- 台商與人力銀行要放照片；外商英文版不放。（104）
- 自傳仍要填，用段落標題＋特殊事蹟，資深者 300～500 字。（104）
- 外商與新創附英文版。（Cheers）
- 檔名「姓名_職位_履歷」，技術名詞寫全名。（Cake）

## 常見扣分 Top 10

職責清單、沒有數字、一份履歷投所有職缺、錯字、版面擁擠、ATS 不可讀、技能大雜燴、數字沒脈絡或膨風、日期缺漏、照片不當或作品集有 bug。
