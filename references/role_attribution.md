# 角色歸屬規則

履歷最常被 reference check 打臉的地方不是數字，是「這件事到底是誰做的」。本專案用下面的規則決定動詞。

## 判斷順序

1. 事實表 `ian_role` 欄位或月報／專案文件的「負責人」欄是唯一依據。
2. 本人親手執行（自己寫程式、訓練模型、赴現場上線、親自授課）→ 可用：開發、訓練、部署、建置、上線、撰寫、授課。
3. 本人是專案負責人、制定方向、做決策、對外負責，但執行是團隊成員 → 用：主導、負責、帶團隊、帶 N 名工程師、督導、規劃、協調、制定。做法段寫「團隊採…」「由團隊實作…」，本人負責「方案取捨、資源調度、對外協調」。
4. 本人只是共同負責人之一、或中途加入 → 用：共同負責、參與、自 YYYY/MM 起負責 X 階段。
5. 本人未列名、但屬於本人管理的團隊成果 → 用：團隊完成、團隊取得（專利、獎項、媒體報導）。
6. 外部廠商做的 → 寫廠商名，本人只寫驗收、監督、整合。
7. 公司層級的決策（採購、外購）若無本人署名紀錄 → 寫「參與評估」「彙整評估依據」，不寫「定案」。

## 常見誤寫

| 誤寫 | 問題 | 改法 |
|---|---|---|
| 主導三套系統的架構與模型訓練 | 模型由成員訓練 | 負責三套系統的方向與資源，其中 X 案親自訓練模型 |
| 主持驗收 | 驗收由成員執行、標準是別人訂的 | 依標準逐月檢核驗收結果 |
| 規劃 300 人導入計畫 | 月報負責人是別人 | 督導成員推動…；本人負責 Y |
| 通過驗收 | 部分項目未達標 | X 項目達標；Y 未達標，已排定複驗 |
| 上線供同仁使用 | 只有「建置中」紀錄 | 2026/07 起建置 |
| 團隊取得專利 → 我的專利 | 發明人未列名 | 團隊取得兩項專利（若本人是發明人再改「共同發明人」） |

## 「主導」配額

全文不超過 4 次。超過代表沒有分化角色，讀者會覺得什麼都是你做的，反而不可信。替代詞：負責、發起、帶、督導、制定、推動、規劃。

## 進行中 vs 完成

事實表若寫「規劃、預計、評估中、建置中、待辦」，履歷只能寫同樣的狀態，或標日期「YYYY/MM 起」。完成式只給有上線、驗收、結案紀錄的事。
